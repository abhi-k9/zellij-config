Anatomy of a Node

everything in KDL is a node: a name, then values, then an optional block
A node is one line of config. It has a name, zero or more arguments (positional values) and properties (key=value), and an optional { } block of child nodes.
tab name="code" focus=true {
    pane size="75%" { name "editor"; }
}
└┬┘ └──────┬──────────────┘ └───────────┬───────────┘
 name    properties            children (more nodes)
More real lines from this config
theme "catppuccin-mocha"
node + one string argument
pane_frames true
node + one boolean argument
copy_on_select true
arguments have no key — position is meaning
ui { pane_frames { rounded_corners true; }; }
blocks nest as deep as you need — on one line, every node needs its ; (see Structure)

Values & Types

"quoted string"the common case; always safe
"with \n \t \" \\"escapes: newline, tab, quote, backslash
"\u{1F600}"unicode by hex code point
42   -5   1.5integers and floats
10000   1_000_ is a legal digit separator
0xff 0o755 0b1010hex / octal / binary
true   falsebooleans zellij v1 style
nullthe null value (rare in zellij)
Watch out — KDL v2: the newer KDL 2.0 spec writes these as #true / #false / #null and raw strings as #"..."#. Zellij 0.45.1 does not accept them — its config and layout parser is KDL v1 only, and v2 syntax is a parse error (verified; even with a kdl-version 2 marker). Write bare true/false and r"…" raw strings.

Comments & Disabling

// lineto end of line — the workhorse
/* block */spans multiple lines
/- nodeslashdash: disable the next whole thing
Slashdash /- comments out the next node, value, or entire { } block — structure-aware, no matching */ to chase. Works in config.kdl (options and keybinds). ⚠ NOT in layout files — zellij's layout parser rejects /- and the whole layout fails to load (verified on 0.45.1). Use // in layouts instead.
Disable without deleting (in config.kdl)
/-scroll_buffer_size 50000   // this option off (uses default)

keybinds {
    normal {
        /-bind "Alt f" { ToggleFloatingPanes; }  // one bind off
    }
}

Arguments vs Properties

the #1 confusion
"F12"argument — a bare value, meaning set by position
size="50%"property — a key=value pair
Rules that bite
Orderarguments are positional (order matters); properties are not
Spacingno spaces around =  →  focus=true, never focus = true
Dupesif a property repeats, the last one wins
Quotesquote any value with spaces, or that looks like a number/keyword
bind "F12" { SwitchToMode "Locked"; }
//   ↑ arg   ↑ child node ↑ its arg

Structure & Tokens

{ }children block — indent is cosmetic, braces are real
;ends a node; lets several share one line. ⚠ zellij: on one line a } does not end a node — end every node with ;, including the last one and each closed block: ui { pane_frames { rounded_corners true; }; }. Without them the file (config or layout) fails to load. Across lines, newlines do this job — no ; needed. (verified on 0.45.1)
\line continuation — wrap a long node
bare-identnames/keys need no quotes if plain
Seen in the keybinds block
bind "F12" { SwitchToMode "Locked"; }
//                              ↑ ';' ends the
//                                inner node
clear-defaults=true — a zellij property (hyphens are fine in bare names) that wipes built-in binds/plugins before yours.

KDL as zellij reads it — gotchas

where KDL and zellij's parser surprise you
silentUnknown / misspelled node names are ignored without error. serialize_pane_veiwport true (note the typo) just does nothing — no warning, the real setting stays at its default.
v1Write true/false, not #true. Copy-pasting v2 KDL from the web makes the whole file fail to parse on 0.45.1.
;On one line, a closing } doesn't end a node — write { floating true; }, not { floating true }, and put ; after each closed block too (…}; }). Otherwise the file won't load. Multi-line blocks need none.
liveZellij watches the file and hot-reloads most options on save — no restart needed to test a change.
errorsReal syntax errors (bad braces, unclosed quote) surface via miette — a pointed, underlined message on the offending line.
mergeConfig is merged from several sources; your config.kdl extends the built-in defaults unless a block sets clear-defaults=true.
quoteWhen in doubt, quote the value. "Alt n" and size="50%" must be quoted; a bare 50% is a parse error.
Quick self-check when an edit doesn't take effect:  1) node name spelled exactly right (typos are silently ignored)?  2) bare true/false, not #true?  3) values that need quotes actually quoted?  4) braces balanced, and on one-line blocks a ; after every node?  zellij setup --check pinpoints 2–4 with a line number; it can't catch 1.
