Verification Checklist — run these on your own machine

zellij 0.45.1
Tier 2 (hardware-dependent)
Automated checks cover configuration parsing and helper regressions against the selected Zellij binary. They do not establish interactive behavior for your terminal. CHANGELOG.md records validation and limitations. Run these checks on your own machine — they need a real terminal, GUI, clipboard, or a reboot. Tick each once confirmed; investigate configuration, application and terminal capabilities when a check fails. Use disposable named sessions for these checks. Shell command examples use a POSIX shell unless marked PowerShell; on native Windows use zj.cmd for the launcher and the equivalent native application commands. Start a new zj session after source/local-preference edits; reconnecting an existing session retains its startup snapshot.

Local clipboard (copy-on-select)

Testscopy_on_select true + copy_clipboard "system"
DoIn any pane, drag-select some text with the mouse. Don't press anything else. Switch to another app and paste (Ctrl/Cmd+V).
PassThe selected text pastes — selection alone copied it to the system clipboard.

Clipboard over SSH (OSC52) if you SSH

TestsOSC52 forwarding through SSH to the local terminal's clipboard
DoSSH into a remote box running this zellij, drag-select text in a pane, then paste into a local app on your laptop.
PassText lands in your local clipboard. Needs an OSC52-capable local terminal (kitty, WezTerm, Ghostty, iTerm2, Alacritty…).
If it failsCheck the local terminal's OSC52 support and clipboard permissions, and any intermediate multiplexer/SSH forwarding settings. A remote pbcopy/wl-copy command normally accesses the remote machine's clipboard.

Mouse behavior

Testsmouse_mode true, focus_follows_mouse false, mouse_click_through false, advanced_mouse_actions + mouse_scroll_resize (both default true, not set)
DoOpen two panes (Alt+n). (a) Click a pane → it focuses. (b) Move the mouse over the other pane without clicking. (c) Drag the border between the two panes, then hold Ctrl and scroll the wheel over a pane. (d) Wheel-scroll a pane.
Pass(a) one click focuses; (b) focus does not follow the mouse on hover; (c) both the border drag and Ctrl+scroll resize the panes (Ctrl+drag is only needed for floating panes, where a plain drag moves them); (d) the wheel scrolls the pane and, since 0.45, the status bar switches to Scroll mode (scroll_mode_sync, default on).

Theme colors

Teststheme "catppuccin-mocha" (confirmed a real built-in; colors are visual)
DoLook at it: dark background, soft mauve/blue/green accents, rounded pane frames.
PassIt reads as Catppuccin Mocha, not zellij's default palette.
BonusIf your terminal supports CSI 2031, uncomment both theme_dark/theme_light lines in config.kdl, start a new zj session, then flip the terminal's light/dark mode. Leave explicit_theme_hue commented: it pins one hue and stops switching. The optional zjstatus bar keeps its own palette.

Desktop notifications if you want them

Testshost_notification_protocol "auto" (forwarding verified; the OS popup is hardware)
DoIn a pane, run: printf '\033]9;build done\033\\' (POSIX \033; \e isn't portable — dash prints it literally) — or run a real long command that emits a notification on finish.
PassA real OS desktop notification appears. Needs an OSC9/99-capable terminal (kitty, WezTerm…) with notifications allowed.

Crash → reattach → nvim :qa safety the important one

Testssession_serialization true + the two-tab default; use a disposable named test session
Do 1. Run zj -s recovery-test -n default → a named session with main + shell tabs.
2. In the main tab, open nvim and edit something.
3. Save your work. Simulate a crash only for this disposable session using your platform's process tools, or reboot when convenient.
4. Reattach: zj attach --create recovery-test.
5. If the main tab returns running nvim without a parent shell, type :qa. Record whether the editor/application state was restored; a plain shell cannot verify this case.
PassRecord whether :qa returns to a shell, leaves a held command pane, or closes the editor pane. If it closes, the retained shell tab remains usable and the session stays alive. Closing the last pane in a single-tab session would instead end it.
NoteThe extra tab helps only while it exists. Editor session plugins and backups can provide separate recovery, but must be tested too. See docs/CONFIGURATION.md.

Reboot recovery

Testssession_serialization across a full machine restart
DoSave work in the recovery-test session, reboot when convenient, then run zj attach --create recovery-test. Use your own session name for normal recovery; no singleton name is configured by default.
PassThe expected tabs and panes return. Compare application state and recent structure changes with what you recorded before reboot. Panes redraw blank because serialize_pane_viewport is off. Record any recovery limitations.

zjstatus status bar renders if you adopt zjstatus

Testslayouts/zjstatus.kdl; clock, colors, frame behavior and optional Git widget need visual checks
DoRun zj -s zjs -n zjstatus. Focus the bar to read and respond to any permission prompt. Toggle frames with Ctrl+p, then z if needed, or save --pane-frames off through the configure helper.
PassThe bar shows mode, session, tabs and UTC clock. With 2+ panes, the swap layout name changes when cycling Alt+], without frame flicker. Git appears only when explicitly enabled and Git is available; verify it against the session's startup directory.
NoteUTC and no Git command are the portable defaults. Configure --timezone Europe/Paris --git-status on locally if wanted, then start a new zj session. Plain zellij ignores the local JSON preferences.

multitask runs commands on save if you use multitask (Linux/macOS)

TestsExplicit opt-in multitask invocation; no Ctrl+o t binding is shipped
Docd into a project in a Unix shell and run zellij action start-or-reload-plugin multitask --configuration "shell=$SHELL,ccwd=$(pwd)". Respond to any permission prompt. In the file opened by your configured editor, add pwd as its own command line and save.
PassA pane runs the command and displays the project directory. Verify command-on-save behavior on your machine.
If it failsRecord the plugin error, permissions, EDITOR and SHELL; compare your invocation with the pinned plugin's documentation.

Ctrl keys and the Windows terminal host native Windows

TestsNORMAL-mode Ctrl+o and Ctrl+p; PowerShell is the shell, Windows Terminal is the terminal host
DoOpen Windows Terminal and choose its PowerShell profile. From the full checkout, run .\launcher\zj.cmd --config-dir . -s keyboard-test -n minimal with an unused session name. Confirm NORMAL; unlock with Ctrl+g for portable defaults or F12 for classic. Press Ctrl+o, Esc, then Ctrl+p, Esc.
PassThe status bar enters Session and Pane mode respectively. The shell does not receive literal [111;5u or [112;5u reports.
RecordTerminal host, native Windows versus WSL, and zellij --version; if ZJ_ZELLIJ_BIN is set, check & $env:ZJ_ZELLIJ_BIN --version instead.
NoteThe same reported config works in Windows Terminal while the older Windows PowerShell console window prints these reports without changing mode. Open PowerShell in Windows Terminal. See the keyboard troubleshooting guide.
